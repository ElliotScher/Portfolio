# Modular LaTeX Resume

This repository contains a modular LaTeX resume system designed for generating multiple, customized versions of a resume from a single, version-controlled source. It uses a Python script to dynamically assemble the resume from small, reusable content blocks based on YAML configuration files.

The entire process is automated using GitHub Actions, which compiles all configured resumes and commits the final PDFs into a `generated/` directory on every push to the `main` branch.

## Features

- **Modular by Design**: Every piece of the resume (experience, projects, skills) is a separate `.tex` file, making it easy to manage and reuse content.
- **Configuration-Driven Builds**: YAML files define which content blocks to include, allowing for easy creation of tailored resumes for different job applications.
- **Fully Automated**: A GitHub Actions workflow handles the entire build process, scanning for configurations, compiling them, and committing the PDFs.
- **Clean and Maintainable**: The main `.tex` file is a clean template, completely separate from the content.

## How It Works

The system is built around four key components:

1.  **`resume/` Directory**: This directory holds all the modular content for the resume, organized into subdirectories like `experience/`, `projects/`, `skills/`, etc. Each `.tex` file in these directories is a self-contained content block.

2.  **`configs/` Directory**: This folder contains `config_*.yml` files. These YAML files define the structure of a specific resume version. Each file specifies which content blocks to include for each section.

3.  **`build_script.py`**: This Python script handles the assembly and compilation. It reads the `.yml` configuration files, generates a temporary `build.tex` file, and calls `pdflatex` to generate the PDF.

4.  **`main.tex`**: This is the main LaTeX template. It sets up the document's formatting, styles, and layout. Its only job is to `\input` the temporary `build.tex` file generated by the Python script.

## Local Development

To build the resume on your local machine, you will need:
- A LaTeX distribution (e.g., TeX Live, MiKTeX) in your system PATH.
- Python 3.
- The `PyYAML` Python package (`pip install pyyaml`).

### Building Locally

The build script has been designed to be as simple as possible. It handles both generating the LaTeX source and compiling it into a PDF.

**1. Build all resumes:**
Running the script with no arguments will scan the `configs/` directory and build a PDF for every `config_*.yml` file it finds.
```bash
python build_script.py
```

**2. Build a specific resume:**
You can build a single resume by passing its name (the part after `config_`). For example, to build `configs/config_full.yml`:
```bash
python build_script.py full
```

**3. Output to a specific directory:**
By default, PDFs are generated in the root directory. To output them to a specific folder (like the automated workflow does), use the `--output-dir` flag:
```bash
python build_script.py --output-dir generated
```

## Customization

### Adding New Content

To add a new project, experience, or skill:
1.  Create a new `.tex` file in the appropriate subdirectory (e.g., `resume/projects/my_new_project.tex`).
2.  Add your LaTeX content to this new file. Do not include any preamble commands like `\usepackage`.
3.  To include it in a resume, add the filename (without the `.tex` extension) to the appropriate list in the desired `configs/config_*.yml` file.

### Creating a New Resume Version

Let's say you want to create a special resume for a robotics software engineering role.

1.  **Create a New Config File**: Create a new file in the `configs/` directory and name it `config_robotics_sw.yml`.

2.  **Customize the Content**: Edit `config_robotics_sw.yml` to include only the most relevant projects and experiences.

3.  **That's It!**: Because the build script and GitHub Actions workflow automatically scan the `configs/` directory, you don't need to update any scripts. The next time the workflow runs, it will automatically build and commit `Resume_Robotics_sw.pdf`.

## Automated Builds

This repository is configured to automatically build all resumes defined in the `configs/` directory whenever changes are pushed to the `main` branch. The workflow is defined in `.github/workflows/build.yml`.

The process is as follows:
1.  The `build` job runs for every push.
2.  It runs `python build_script.py --output-dir generated`. The script automatically finds all configs, builds the PDFs, and places them in the `generated/` directory.
3.  The `commit` job runs after the build job and commits the contents of the `generated/` directory back to the repository in a commit authored by `github-actions[bot]`. The commit message includes `[skip ci]` to prevent the workflow from triggering itself in a loop.
