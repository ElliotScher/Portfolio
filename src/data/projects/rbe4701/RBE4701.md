## Summary

**Bomberman AI** is a pair of autonomous decision-making agents developed for WPI's RBE 4701 (AI for Robotics) course projects. Each agent controls a character in a grid-based Bomberman world and must reach the exit while monsters with different behaviors roam the map. **Project 1** combines A* path planning with a precomputed Markov Decision Process (MDP) solved by value iteration to dodge monsters. **Project 2** adds walls that block every route to the exit, so the agent must learn where and when to place bombs. It uses approximate Q-learning with a finite state machine, hand-built features, and a safety shield. Both agents use a single shared approach across all five scenario variants rather than separate per-variant logic.

***

## Context

Grid-world games are a compact stand-in for real robot decision-making problems: an agent has to plan a route, predict the behavior of other agents it doesn't control, and act under uncertainty with a limited view of the consequences of each move. The Bomberman environment provides five increasingly difficult variants:

* **Variant 1**: The agent is alone in the world.
* **Variant 2**: A "stupid" monster moves uniformly at random.
* **Variant 3**: A self-preserving monster walks straight until it hits an obstacle and attacks if the agent comes within one cell.
* **Variant 4**: An aggressive monster actively chases the agent once it is within two cells.
* **Variant 5**: Both a stupid monster and an aggressive monster are present.

The design goals for both projects were:
* Use one approach for all five variants instead of hand-tuning a separate solution per scenario.
* Exceed the required 50% escape rate on every variant.
* Make decisions fast enough to evaluate the agents over thousands of headless games.

## Project 1: A* and Value Iteration

The Project 1 agent switches between two behaviors depending on how close the monsters are:

* **A\* Path Planning**: With no monster within seven tiles, the agent follows the shortest A* path to the exit. Because diagonal and straight moves cost the same, Chebyshev distance is used as an admissible heuristic, with Euclidean distance only as a tie-breaker.
* **MDP Value Iteration**: Since the walls and exit never change, the problem is modeled as an MDP whose state is the pair of character and monster positions. Value iteration runs once on the first step a monster is present, using rewards of +10,000 for reaching the exit, -10,000 for entering the monster's attack range, and -1 per step, with a discount factor of 0.9. The cached value table is then reused for the rest of the game.
* **State Space Reduction**: Only character/monster pairs within a Chebyshev distance of seven are solved, reducing the 18,496 possible pairs on the 136-cell map to 11,488 states (about 38% fewer).
* **Monster Prediction**: A single conservative model is used for every monster. Within two cells, a monster is assumed to chase the agent along the move that most reduces its BFS shortest-path distance. Farther away, it is modeled as moving uniformly at random, which gives the MDP its stochastic transitions.

## Project 2: Approximate Q-Learning

In Project 2, every route to the exit is blocked by walls, so the agent must bomb its way through while surviving its own explosions. Each step, it scores ten actions (eight moves, stay, and bomb) with a linear Q-function.

* **Finite State Machine**: Four states, NAVIGATE, BREACH, WAIT_BLAST, and ESCAPE_BLAST, are checked in priority order, and each has a no-monster twin. The state doesn't restrict actions. It only selects which of the eight learned weight vectors scores them.
* **Breach Distance Features**: The core feature is "breach distance", the shortest path to the exit when walls cost 6 instead of 1, which lets the agent compare walking around against bombing through using one metric. In total, 29 normalized features cover progress, open space, bomb usefulness, blast survival, and BFS-based monster proximity.
* **Safety Shield**: Bomb deaths are hard to learn because the fatal action happens several steps before the -100 reward. A shield masks illegal actions and any action that leads to certain death or leaves too little time to escape a blast, so learning can focus on monster avoidance and good bombing spots.
* **Reward Shaping**: Rewards of +1 for progress toward the exit and +5 per destroyed wall give the agent feedback long before it ever reaches the exit by random exploration.
* **Training and Pruning**: Each variant was trained headlessly from zero weights over four independent runs with different seeds, exploration rates, and learning rates, keeping the best checkpoint. Features were then pruned by measuring how often each one changed the chosen action and how many escapes were lost without it. This cut Variant 1 down to just 4 features and reduced its average escape time from 79 to 71 steps.

## Testing and Tooling

Stepping through the rendered game was far too slow to evaluate changes, so the team built a headless test harness that runs thousands of games without rendering. It was wrapped in Pytest and run by GitHub Actions on every pull request, and changes could not be merged until the tests passed. Every game is seeded, so any failure can be replayed exactly.

## Results

Both agents cleared the 50% requirement on every variant. Project 2 averaged an 89.8% escape rate across more than 600,000 evaluation games, even though it also had to clear walls. It improved on Project 1 in Variant 5 (81.7% to 90.4%) and matched it in Variant 4, where the aggressive monster remained the hardest case. The videos below were recorded from the final agents.
