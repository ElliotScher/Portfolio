# Per-Project Development Shells

Alongside the machine configuration, `dev/` holds standalone Nix flakes — one per project (`Portfolio/`, `Acadia_AI_E26/`, `FRC/`) — that provide a pinned `devShell` for that project's toolchain, independent of whatever happens to be installed on the host system. Running `nix develop` (or letting `direnv` do it automatically via the Home Manager `nix-direnv` integration) drops into a shell with exactly the right compiler, interpreter, or Node version, with no risk of it drifting from what's declared in the flake.

## A Shared Welcome Banner

Every dev shell prints a consistent welcome banner — a bar, a centered title, another bar, and an optional subtitle — generated by a small shared helper, `dev/lib/shell-banner.nix`, instead of each flake hand-formatting its own ASCII art:

```nix
{ title, subtitle ? null, width ? 60 }:
''
  BAR_WIDTH=${toString width}
  BAR=$(printf '=%.0s' $(seq 1 $BAR_WIDTH))
  center() {
    text="$1"
    len=$(printf '%s' "$text" | wc -c)
    pad=$(( (BAR_WIDTH - len) / 2 ))
    printf '%*s%s\n' "$pad" "" "$text"
  }
  echo "$BAR"; center "${title}"; echo "$BAR"
  ${if subtitle != null then ''center "${subtitle}"'' else ""}
''
```

Padding is computed at shell startup rather than hand-typed, so the banner stays centered no matter how long a given project's title or subtitle ends up being.

## Example: the Portfolio Shell

This portfolio's own `dev/Portfolio/flake.nix` pins Node.js 22 and Chromium, and points Puppeteer (used by `scripts/build-resumes.js` to render resume PDFs) at nixpkgs' Chromium build instead of letting Puppeteer download its own — which doesn't work reliably on NixOS, since a generically-downloaded Chromium binary expects dynamic linker paths that don't exist outside of `nixpkgs`' patched build:

```bash
export PUPPETEER_SKIP_DOWNLOAD=true
export PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true
export PUPPETEER_EXECUTABLE_PATH="${pkgs.chromium}/bin/chromium"
```

The shell hook also compares `package-lock.json`'s modification time against the `node_modules` directory on every entry, automatically running `npm install` only when the lockfile is newer — so dependencies stay in sync without a manual install step, and without reinstalling on every single shell entry.
