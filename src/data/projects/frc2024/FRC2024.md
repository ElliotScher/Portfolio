## Summary

**FRC 190 2024 Codebase** is a unified, command-based Java robot controller built on the WPILib framework for FRC Team 190's 2024 competition season. The codebase is designed around a single-repository, multi-robot design pattern that concurrently supports two separate physical robots: **Snapback** (an adjustable-hood shooter robot) and **Whiplash** (a pivot-arm shooter robot). Using AdvantageKit for hardware abstraction, the codebase enables full simulation capabilities and deterministic log-replay testing across these distinct hardware architectures. It integrates advanced automation, featuring automatic path planning to the Amp scoring station, dynamic shooter parameter interpolation based on target distance, and computer vision machine learning to dynamically target Notes and replan paths on the fly.

For a detailed explanation of the multi-robot deployment safety verification and Gradle routing task, see the [FRC Shared Codebase Design & Execution](#/projects/FRCSharedCodebase) project page.

## Context: The FRC Crescendo Challenge

In the 2024 FRC game, *Crescendo*, robots were challenged to collect orange toroidal foam game pieces called **Notes**, transport them, and score them into target structures:
* **The Speaker**: A high goal requiring high-velocity note shots, often from variable distances and angles on the field.
* **The Amp**: A low goal requiring a precise downward-deposit mechanism.
* **Note Feeding**: Fast note shots passed from defensive zones to offensive zones.

## Robot Iterations

Throughout the 2024 season, Team 190 developed three completely separate parallel robot builds, all of which competed in official events:
* **V1 (Snapback)**: First robot featuring a floor intake and an adjustable shooter hood (`SnapbackHood`) designed for rapid speaker scoring from variable distances.
* **V2 (Whiplash)**: Second robot built with a 1-DOF pivot arm (`WhiplashArm`) carrying a flywheel shooter, enabling scoring in both the high Speaker and low Amp goals.

## Key Technical Features

Instead of relying on basic driver controls, the 2024 codebase focuses on high-level automation to optimize scoring cycles and adapt to dynamic match conditions:

### 1. Automatic Pathing to Score in the Amp
Scoring in the Amp requires aligning the robot's scoring mechanism with a small vertical opening on the field wall. To eliminate driver alignment delay, the codebase features an automated pathing routine:
* **Dynamic Trajectory Generation**: When the driver triggers the Amp routine, the robot locks out manual controls and uses its current state-estimated pose to plan a smooth, time-parameterized path directly to the Amp coordinates.
* **Closed-Loop Driving**: The swerve drivetrain automatically follows the trajectory using translation and rotation PID controllers, aligning the robot precisely bumper-to-wall.
* **Simultaneous Mechanism Deployment**: As the robot drives along the path, the intake and scoring mechanism (such as Whiplash's pivot arm) automatically deploy to the scoring position (`WhiplashArmGoal.AMP`). The robot arrives at the Amp fully aligned with the arm deployed, scoring the note immediately upon arrival.

### 2. Automatic Shot Angle and Speed Interpolation
To allow the robot to shoot into the Speaker from anywhere on the field, the codebase calculates shooting parameters dynamically based on visual state estimation:
* **Distance Calculation**: The robot constantly calculates its Euclidean distance from the Speaker goal using its fused pose.
* **Parameter Interpolation**: The software queries double-interpolated lookup maps (`InterpolatingDoubleTreeMap` and `InterpolatingTreeMap` in [RobotState.java](file:///home/elliotscher/Documents/Misc/Portfolio/src/data/projects/FRC2024.md)) to calculate the exact launch angle and flywheel velocities for that distance:
  - **Launch Angle**: Adjusts the motorized shooter hood angle on *Snapback* or the pivot arm angle on *Whiplash*.
  - **Flywheel Speed**: Adjusts dual-flywheel motor velocities to ensure optimal note trajectory.

### 3. Midline Note Detection & A* Path Replanning
Autonomous routines in FRC are highly competitive, especially when attempting to collect "midline" notes placed at the center of the field:
* **Computer Vision Machine Learning**: Dual cameras interface with a coprocessor running a machine learning object-detection model. The model identifies the 3D position of orange Notes on the carpet in real time.
* **Dynamic Autonomous Target Selection**: Rather than following a rigid path, the robot's autonomous routine uses the ML detections to target the nearest note. If a note is missing (e.g., collected by an opponent), the robot dynamically changes its target and adapts its routine on the fly.
* **A* Path Replanning**: If the robot is bumped or blocked by defensive opponents, it uses an A* pathfinding algorithm on the RoboRIO to calculate a new collision-free path back to its target trajectory in real time, avoiding obstacles and maintaining scoring speed.
