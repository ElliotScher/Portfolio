### Why PyTorch

PyTorch is the tensor engine underneath nearly every learned model in Park Vision, at three different levels of abstraction:

- **Ultralytics YOLO**: The general-purpose person/bicycle/vehicle detector, the pose-keypoint model used for pedestrian direction, and the license-plate localizer are all Ultralytics YOLO checkpoints — Ultralytics builds directly on PyTorch, so `model.predict()` calls straight into PyTorch's autograd-free inference path underneath.
- **A Bare PyTorch Checkpoint, No Framework Wrapper**: The vehicle-direction model (`models/vehicle_direction/last.pt`, fine-tuned on the CarFusion dataset to output 14 keypoints per car) isn't an Ultralytics-native model — it's loaded and run through a hand-written PyTorch inference wrapper in `vehicle_direction.py`, since the checkpoint comes from third-party CarFusion research code, not Ultralytics' model zoo.
- **A Custom Re-Identification Network**: The occupancy-profiling pipeline builds a `torchvision.models.resnet50` backbone with its classification head swapped for `nn.Identity()` and its average-pool layer replaced with a hand-implemented Generalized-Mean (GeM) pooling layer — a well-known image-retrieval trick for sharpening a feature embedding's discriminative power. That kind of surgical, layer-level modification needs PyTorch's raw `nn.Module` flexibility rather than a higher-level training framework.
- **CPU Wheel Index**: Because the desktop app targets ordinary ranger laptops, `pyproject.toml` explicitly overrides `torch`/`torchvision` to install from PyTorch's `cpu` package index rather than the default CUDA-enabled build, keeping the installed footprint small and avoiding a GPU-driver dependency the deployment target doesn't have.
