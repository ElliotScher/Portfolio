## Summary

**Robotic Navigation** is an autonomous maze-solving and environment-mapping system developed for WPI's RBE 3002 (Unified Robotics IV: Navigation) lab. Operating on a TurtleBot3 Burger differential-drive robot platform, the system integrates a 2D LiDAR, wheel encoders, and an IMU. Built as a set of custom nodes in **ROS 2 (Robot Operating System)** using **Python**, the navigation pipeline combines Simultaneous Localization and Mapping (SLAM), Adaptive Monte Carlo Localization (AMCL), Euclidean-distance-based A* path planning, Configuration Space (C-Space) obstacle inflation, and a frontier exploration state machine. The final system is capable of autonomously exploring and mapping an unknown enclosed environment, calculating collision-free paths, and navigating safely to target coordinates.

## Context

In mobile robotics, autonomous navigation within unknown or unstructured environments is a foundational capability. A mobile robot must be able to explore its surroundings to build a reliable metric map, compute collision-free trajectories through narrow corridors and around sudden obstacles, and track its position in real time despite wheel slippage, sensor noise, and environmental uncertainty.

To address these requirements, this project implements a complete, modular perception-to-action navigation stack on the TurtleBot3 platform. The robot is placed in an unknown walled maze with no prior map. It must autonomously map the environment, identify boundaries, plan optimal paths, and execute precise motion commands to solve the maze without human intervention.

### Mapping, Localization, and Path Planning

To navigate and map the environment autonomously, the system executes a tightly coupled loop of spatial reasoning, planning, and control:

* **SLAM & Occupancy Grid Mapping**: Raw 2D LiDAR range measurements are paired with the robot's calculated position to construct a probabilistic occupancy grid. The grid maps physical coordinates into discrete cells containing probability values (e.g., `0` for known free space, `100` for occupied obstacles, and `-1` for unknown space). Ray casting translates continuous range vectors into grid cell coordinates, updating cell probability states using a binary log-odds representation to handle sensor noise and transient obstructions.

* **C-Space Inflation & Costmap Generation**: Before planning paths, the occupancy grid is processed to generate a costmap. To protect the robot, obstacles are inflated by applying a Configuration Space (C-Space) dilation. A safety buffer (matching the physical dimensions of the TurtleBot plus a safety margin) is projected around every occupied cell. Cells near walls are assigned gradient costs that decrease with distance, guiding the path planner to prefer paths that run down the middle of corridors rather than hugging the walls.

* **A* Path Finding**: Utilizing the generated costmap, the path planning node computes the shortest collision-free route using the A* search algorithm. The search evaluates cells using a cost function $f(n) = g(n) + h(n)$, where $g(n)$ represents the accumulated travel cost (including distance and obstacle proximity gradients) from the starting point to cell $n$, and $h(n)$ is the Euclidean distance heuristic to the goal. A* explores the grid space, resolves backtracks, and returns an ordered list of waypoints representing the optimal trajectory.

* **Frontier Detection & Clustering**: For autonomous exploration, the robot must determine where to navigate next. The system scans the grid for "frontier cells" - known free space cells that directly border unknown cells (`-1`). These cells are grouped into spatial clusters using density-based clustering (like DBSCAN) to filter out single-cell noise. The system computes the centroid of each cluster, scores candidate frontiers based on their size (exploration reward) and distance from the robot (movement cost), and selects the highest-scoring centroid as the next navigation goal.

* **AMCL & Trajectory Tracking**: To move along the A* waypoints, the robot integrates Adaptive Monte Carlo Localization (AMCL) to maintain an accurate pose estimate. AMCL uses a particle filter to continuously align LiDAR scans with the static map features, compensating for encoder drift and wheel slippage. A waypoint tracking controller translates the planned path coordinates into smooth velocities. It calculates heading errors and distance offsets, outputting translational and angular velocity commands (`geometry_msgs/Twist`) to guide the robot along the trajectory.
