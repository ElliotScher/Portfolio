## Summary

**FRC 190 2025 Codebase** is the robot control software designed for FRC Team 190's 2025 competition season, competing in the FRC game *Reefscape*. The codebase is built on the WPILib framework in Java and utilizes a modular, single-repository multi-robot pattern to support three separate physical robots: **V1 (StackUp)**, **V2 (Redundancy)**, and **V3 (Poot)**. Utilizing AdvantageKit for telemetry logging and simulation, the codebase features advanced autonomous systems across these distinct hardware architectures, including dynamic A* pathfinding and alignment to the hexagonal Reef, and a directed graph-based state machine that calculates collision-free movement profiles for the multi-axis elevator superstructure.

For a detailed explanation of the multi-robot deployment safety verification and Gradle routing task, see the [FRC Shared Codebase Design & Execution](#/projects/FRCSharedCodebase) project page.

## Context: The FRC Reefscape Challenge

In the 2025 FRC game, *Reefscape*, robots score cylindrical **Coral** game pieces onto a large central hexagonal structure known as the **Reef** (featuring 12 scoring branches across L1, L2, L3, and L4 heights). Additionally, robots must clear green **Algae** balls hanging on the Reef and score them into the **Barge** goal.

## Robot Iterations

Throughout the 2025 season, Team 190 built three completely separate parallel robot builds, all of which competed in official events:
* **V1 (StackUp)**: First robot utilizing a vertical elevator lift and custom swerve geometry.
* **V2 (Redundancy)**: Second robot featuring reinforced elevator stages, and upgraded manipulator to score algae.
* **V3 (Poot)**: Third robot incorporating an optimized multi-axis superstructure, and a high-speed climber.

## Key Technical Features

To handle the precise positioning requirements of the Reef structure and the multi-axis complexity of the final robot, the codebase incorporates three major control systems:

### 1. Dynamic Path Planning and Aligning to Reef Branches
Scoring Coral at the L2, L3, or L4 heights requires aligning the robot's manipulator precisely with a specific vertical branch on the hexagonal Reef:
* **AprilTag Field Positioning**: The swerve drivetrain combines wheel odometry with visual updates from multi-camera AprilTag map estimates to track coordinate positions.
* **Automatic Target Routing**: When the driver requests a specific Reef level and branch, the robot automatically generates a smooth path to align itself bumper-to-Reef. The swerve drive rotates to match the targeted Reef face on the fly.
* **Closed-Loop Alignment**: Translation and rotation PID controllers ensure the robot locks onto the branch with millimetric precision, eliminating driver alignment errors.

### 2. Directed Graph Superstructure State Machine
Multiple competition robot's superstructures consists of components with internal collisions that needed to be avoided.
* **Directed Graph representation (`DefaultDirectedGraph`)**: Subsystem configuration limits and positions are represented as vertices in a directed state graph.
* **BFS Pathfinding**: When a target state is set, a Breadth-First Search (BFS) algorithm calculates the shortest, safest sequence of intermediate movements (edges).
* **Collision-Free Transitions**: The elevator, pivot, and gripper transition through coordinates sequentially. This ensures that the elevator only raises after the arm has retracted to a safe position, preventing physical self-collisions.

### 3. Onboard AprilTag Localization via GompeiVision
To achieve the high accuracy required for automatic Reef alignment, the robot's localization system relies on Team 190's custom vision stack in the offseason:
* **Dedicated Coprocessor Offloading**: The robot runs [GompeiVision](#/projects/GompeiVision) on an onboard Linux Mini PC. This offloads the high-overhead task of processing multi-camera USB streams, AprilTag detection, and 3D Perspective-n-Point (PnP) pose solving from the main RoboRIO processor.
* **High-Frequency Sensor Fusion**: The RoboRIO receives 3D translation and rotation vectors from GompeiVision over standard NetworkTables. These updates are fused with drivetrain wheel encoders and gyro data in a WPILib pose estimator, keeping the robot's coordinate map constantly synchronized.
* **Latency Compensation & Filtering**: The codebase implements custom latency compensation to apply vision updates at the exact timestamp the frame was captured, along with quality filters that reject detections with high ambiguity or excessive distance.
